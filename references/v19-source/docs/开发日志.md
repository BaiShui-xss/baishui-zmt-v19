## 一、项目背景与目标

**新媒体运营工作台**是一款面向新媒体运营的 PWA（Progressive Web App），目标是把分散的账号管理、灵感记录、任务跟踪、内容选题、数据复盘、周期报告整合进一个可离线、可装到手机的单页应用。

核心约束（来自设计偏好与架构决策）：
- **纯前端单页应用**，数据默认存浏览器 `localStorage`，可选接 Node + SQLite 后端做多设备同步。
- **视觉规范：中性深灰、不要蓝调**。背景纯黑 `#000`，面板层级 `#0c0c0c / #141414 / #1d1d1d`，天蓝仅作功能性高亮色（激活态 / 进度条 / 状态点）。
- 跨设备统一访问：最终采用 CloudStudio 固定公网 HTTPS 地址。

## 二、完整开发历程（叙事版）

### 阶段 0 · 原型与设计定调
- 先用 `prototype.html` 做设计原型，验证布局与「中性深灰无蓝调」视觉。
- 最初面板偏蓝、缺少高级感，按用户反馈改为以 `#808080` 灰为基准的深灰层级，背景光晕/网格改为中性灰，品牌色仅保留为功能性强调。
- 确定模块划分：**核心 4 件**（备忘录 / 待办 / 提醒 / 多账号面板）+ **Phase 3 扩展 4 件**（发布日历 / 选题素材库 / 数据看板 / 周月报）。

### 阶段 1 · Phase 1 MVP（核心 4 模块）
- 落地正式 `index.html` + `assets/css/style.css` + `assets/js/store.js` + `assets/js/app.js`。
- `store.js` 定义状态、`migrate()` 缺省字段兜底、`JSON 导入/导出`、`KEY=ops-workbench-v2`。
- `app.js` 实现侧栏导航、折叠侧栏、各模块渲染、新建/编辑弹窗、备份/导入、PWA 注册。
- 引入 `manifest.webmanifest` 与 `sw.js`（cache-first），支持「添加到主屏幕」当 App 用。
- 生成图标脚本 `gen_icons.py`（纯标准库），产出 `assets/icons/icon-*.png`。

**踩的坑**：JS 字段回填未做空值保护，后续在编辑弹窗暴露为崩溃（见 v16 修复）。

### 阶段 2 · Phase 2 同步后端（Node + SQLite）
- 新增 `server.js`：用 `node:sqlite`（零依赖）实现同步后端，数据存 `data/ops.db`。
- 服务**双端口**：HTTPS `:5173`（手机 PWA 自签证书）+ HTTP `:5174`（Mac 本机/内置预览，零证书摩擦）。
- `SYNC` 默认关闭，用户可在设置中填后端地址开启三套同步逻辑（apiPing / pullState / 轮询）。

**踩的坑（运维类，影响深远）**：
1. **launchctl 注册被 WorkBuddy 沙箱拦截**：在 WorkBuddy 的 Bash 里 `launchctl bootstrap` 一律报 `Bootstrap failed: 5: Input/output error`，但 `launchctl print` 可读——说明沙箱挡住了写操作。最终改为在**用户真实「终端」App** 里手动注册 plist。
2. **iOS HTTPS-Only**：Safari 的「仅限 HTTPS」会把本地 HTTP 强制升级，导致「网址无效」。催生双端口方案 + 证书信任流程。
3. **自签证书 IP SAN**：证书用 `openssl` 生成（有效期 825 天），含 `localhost/127.0.0.1/内网IP`，手机需「设置→通用→VPN与设备管理」信任一次；Mac 内网 IP 变更会导致 SAN 不匹配。
4. **手机顶栏竖排文字 bug**：小屏下顶栏标题区被右侧按钮挤成单字竖排，后在 `@media(max-width:860px)` 改为垂直堆叠修复。

### 阶段 3 · Phase 3 扩展 4 模块
按设计逐个落地：
- **发布日历**：`renderCalendar` 按日期聚合待办/提醒/选题，单日详情与新建入口。
- **选题素材库**：`state.topics` 数据模型 `{id, accountId, title, body, tags[], status, pinned, createdAt}`，`status` ∈ `idea(灵感,灰)/draft(草稿,蓝)/ready(待发,琥珀)/published(已发,绿)`；支持搜索、状态过滤 chips、点击编辑/删除；`load()` 加迁移防崩溃。
- **数据看板**：`state.metrics` 模型 `{id, accountId, date, followers, views, likes, comments}`；纯 SVG 多线趋势图（按账号分色、按日期对齐），账号对比卡（最新值 + delta，涨绿跌红），指标切换 chips；近 6 天示例数据 seed。
- **周/月报**：`renderReport` 按本周(周一~今)/本月(1号~今)聚合完成待办、计划发布、已发布、新增选题、新增备忘，生成 Markdown 预览，支持复制 / 下载 `.md`。

### 阶段 4 · 部署拓扑演进（弯路最多）
- **尝试 A · 局域网 IP + 自签证书**：IP `192.168.1.83` 在手机端常因「仅限 HTTPS」/AP 隔离/解析失败打不开；且最大痛点是**地址会变**。
- **尝试 B · Pinggy 动态隧道**：解决公网可达，但**每 60 分钟地址就变**，无法稳定「添加到主屏幕」。→ 废弃。
- **尝试 C · CloudStudio 固定公网部署（定案）**：纯静态站 + localStorage 优先，整个 App 可脱离 Node 后端运行；部署到固定 HTTPS 地址 `https://b5053b29b4f74f0293cbae7a057ab833.sh4.agentos-app.net`，手机电脑同一入口、长期不变、证书正规。
  - 代价：CloudStudio 静态托管**不跑 Node**，故「跨设备真正共用一份数据」需另部署后端（用户暂选手动 JSON 迁移，未自动化）。
- 配套 `open.html` + `assets/qr-phone.png` 二维码，避免手机手动输入地址出错。

**自验证工作流（无浏览器环境下确立）**：
1. `node --check` 过 JS 语法；
2. Node 脚本交叉比对 `app.js` 引用的 `#id` / `getElementById` 是否都存在于 `index.html`（抓白屏根因，动态字段 `f_*` 排除）；
3. 改完 `workbuddy_cloudstudio_deploy` 同目录原地更新；
4. `curl` 逐项断言 200 + 关键字符串；
5. 资源改动 **bump `sw.js` 的 CACHE** 版本。

### 阶段 5 · 验收与修复（v15 → v19，本轮会话）
- **v15 验收基线**：用 Playwright（Chromium，iPhone 13 视口 390×844）跑 86 项断言；初测 **69 PASS / 12 FAIL**。
- **v16 首轮修复**：修 3 个 P0（编辑弹窗崩溃、待办勾选无效、弹窗关闭按钮超界）+ 4 个 P1（移动端个人资料入口、看板图表窄屏字号、启动 404、favicon），回归 86/86 PASS。
- **v17 日期溢出第一轮**：用户反馈 iOS 上「触发时间/截止日期」超宽。本地加 `min-width:0;max-width:100%` 与 `.row2` 改 `minmax(0,1fr)`。真机仍溢出。
- **v18 版本标识**：新增「设置 → 关于」显示程序版本 + Service Worker 缓存版本，便于确认冷启动是否生效。真机确认已是最新版但仍溢出 → 坐实是**真实 iOS Safari 专属渲染行为**。
- **v19 真机修复**：移动端加 `-webkit-appearance:none`（iOS 上退化为可收缩输入框、点按仍弹原生选择器），补 `overflow-x:hidden` 兜底。用户确认「终于解决了」。

**关键弯路**：本机装了 WebKit（Playwright v2311）仍无法复现 iOS 日期溢出——因为开源 WebKit/Chromium 早已修复「日期输入固有最小宽度不吃 `min-width:0`」这个老 quirk，只有 Apple 官方 iOS Safari 保留该行为。最终靠「真机反馈闭环」才定位。

## 四、技术债务与遗留项

1. **跨设备真同步未自动化**：CloudStudio 仅静态托管，不跑 Node；手机↔电脑共用一份数据需另部署同步后端并填入设置（用户暂选手动 JSON 迁移）。
2. **本地 launchd 后端仅桌面兜底**：`com.workbuddy.opsworkbench.plist` 在真实终端注册才生效，非 WorkBuddy 内自启。
3. **无单测/无 git 历史**：仅靠 `node --check` + DOM id 交叉 + curl + Playwright 断言做回归，版本早期为阶段级记录。
4. **Playwright 仅 Chromium + 后装 WebKit**：均无法复现 iOS Safari 日期 quirk，真机问题依赖用户反馈闭环。

## 五、可复用经验

1. **PWA 改前端必须 bump `sw.js` CACHE**，否则手机持续用旧缓存；用户侧可通过「设置 → 关于」的「运行中缓存」核对。
2. **本机浏览器 ≠ 真机浏览器**：iOS Safari 保留日期输入固有最小宽度老问题（开源引擎已修复），本地不可复现时优先怀疑平台差异，用 `-webkit-appearance:none` + `overflow-x:hidden` 兜底，靠真机闭环。
3. **越界部署优先固定地址**：动态隧道/局域网 IP 皆因「地址会变」失败，固定公网静态托管最稳。
4. **沙箱限制命令**：`launchctl bootstrap` 等写系统级操作须在真实终端执行，不能在 WorkBuddy Bash 内。
5. **自验证三件套**：`node --check` → DOM id 交叉比对 → `curl` 断言线上资源，可低成本守住质量门。
