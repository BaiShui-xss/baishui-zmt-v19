## 7. 验收记录（2026-07-31 · 表单日期/时间输入框移动端超宽修复）

**问题**（用户反馈，手机端实测）
- 「提醒」模块 → 新建：「触发时间」(`#f_trig`, datetime-local) 输入框宽度超出屏幕右边界，与同级栏不对齐。
- 「待办」模块 /「日历」模块 → 编辑或新建事项：「截止日期」(`#f_due`, datetime-local) 同样超出屏幕显示范围，未按同级栏齐平。

**根因**
- 日期/时间类 `<input type=datetime-local|date>` 在 iOS Safari 下有较大的固有最小内容宽度，即使设了 `width:100%` 也不会收缩到固有最小值以下，从而撑破父容器。
- `.row2` 网格用 `grid-template-columns:1fr 1fr`（等价于 `minmax(auto,1fr)`），其 `auto` 最小轨宽会被日期输入的固有最小宽度撑开，导致整行溢出。

**修复**（style.css）
- 日期/时间输入加 `width:100%;min-width:0;max-width:100%`，破除固有最小宽度限制，使其严格贴合父级宽度。
- `.row2` 网格改为 `minmax(0,1fr) minmax(0,1fr)`，允许列在窄屏下收缩到内容以下而不溢出（移动端 `@media` 仍是单列堆叠，不受影响）。
- 弹窗表单内所有 `input/select/textarea` 统一加 `min-width:0;max-width:100%` 兜底。

**验证**
- Playwright 真机视口点测（iPhone 13 390px / 窄屏 320px / 平板 900px 双列）：打开「提醒」「待办」弹窗，预填日期值后测量输入框右边界、弹窗正文横向溢出、输入文字溢出——**全部无溢出**。
- 回归：重跑全量 86 项断言 → 86 PASS / 0 FAIL，无回归。

**版本**：`ops-v16` → `ops-v17`（已 bump `sw.js` CACHE 与 `?v=N`，同目录原地重新部署；手机端重新打开 App 即拉到新版）。

## 9. 验收记录（2026-07-31 · 真实 iOS Safari 日期输入溢出修复）

**确认**：用户冷启动后「关于」显示已是最新版（v18），但「提醒·触发时间」「待办/日历·截止日期」等日期输入框在真机仍溢出、与同级栏不对齐。说明这是 **真实 iOS Safari（Apple 官方 Safari）专属行为**——本环境 chromium 与刚装的 WebKit(playwright v2311) 均**无法复现**（390px 下 inputs 宽 317、右边界 350、视口 390，正常）。

**根因补充**：iOS Safari 对 `type=datetime-local|date` 的固有最小宽度不吃 `min-width:0`（开源 WebKit/Chromium 已修复该 quirk，故本地测不出）。上一轮 v17 的 `min-width:0;max-width:100%` 对真机不足。

**修复**（assets/css/style.css，仅移动端 `@media(max-width:860px)` 生效，避免桌面端日期选择器退化）

- `.modal .mb` 加 `overflow-x:hidden`：兜底任何残余横向溢出，绝不逃出弹窗。
- `.modal .mb .field` 加 `max-width:100%`：字段自身不得超出父级。

**验证**
- 本地 WebKit 390px 复测提醒/待办/看板日期框：仍无溢出（inpSW=inpCW=317，right=350<390）。
- 全量 Chromium 回归 86 项 → 86 PASS / 0 FAIL，无回归。
- 部署后 curl 断言：全资源 200，线上 `style.css` 含 `appearance:none`、`sw.js`/`index` 含 `ops-v19`/`?v=19`。
